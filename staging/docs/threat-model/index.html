Threat model

Product assets and actors

Section titled “Product assets and actors”

Shunter consists of the desktop editor/debugger, shunt runner, GitHub Action, Windows installer, Linux AppImage, downloaded runner archives, Flowbooks and generated reports. Actors include the user, commands and scripts inside a Flowbook, CI provider, GitHub Action dependencies, and anyone who receives a shared report.

A Flowbook executes with the permissions of the user or CI agent. It can run processes, read/write files and use the network through its tasks. Shunter does not sandbox it. Review Flowbooks before running them, especially those from pull requests.

Pull requests and secrets

Section titled “Pull requests and secrets”

A pull request can change a Flowbook or its commands. A fork pull request must be treated as untrusted code. Do not expose repository secrets to untrusted pull requests; the Action also skips publishing JUnit results for fork PRs, but that is not a sandbox. Restrict CI permissions and secrets according to the CI provider’s fork-PR controls.

The GitHub Action downloads an exact-version runner ZIP or tarball and its checksum from the configured GitHub release, validates the checksum and version, then caches the extracted runner. It uses actions/cache@v4, actions/upload-artifact@v7, and dorny/test-reporter pinned to commit a43b3a5f7366b97d083190328d2c652e1a8b6aa2. These dependencies and GitHub cache/artifact services are part of the CI supply chain.

Pauses and debugging

Section titled “Pauses and debugging”

--break, --break-on-failure and --pause-timeout are runner options and work in local or headless CI runs. A CI pause emits a console notice and waits for the configured timeout; the job remains occupied and the provider’s job timeout still applies. The runner resumes after the pause timeout; Ctrl+C cancels. There is no desktop attach to a CI run and no relay in this preview.

Sensitive data

Section titled “Sensitive data”

Flowbook variables and environment entries use the sensitive key. Name-based masking is implemented by isSensitiveVariableName and matches case-insensitive names containing token, secret, password, passwd, apikey, api_key, or credential. Explicitly sensitive values and recognised names are masked in console output, recorded logs, HTML, JSON and Markdown reports, CI annotations, debugger snapshots, and environment values shown by the app. Known secret values are also redacted from captured text. This cannot catch transformed, split, unknown or deliberately re-encoded secrets; commands can disclose their own inputs.

Reports and sharing

Section titled “Reports and sharing”

An HTML report can be shared as a portable file. It may contain task names, output, run inputs, environment metadata, working directories, paths, captured values and resource/process details. Links in the report can reveal local paths or CI artifact locations. Inspect reports before publishing them. Redaction is best effort, not a guarantee against intentional disclosure.

Installation privilege

Section titled “Installation privilege”

The Windows installer installs under {autopf}\Shunter, creates shortcuts and registers the .flowbook association under HKCR. Inno Setup’s default privilege mode applies (normally requests elevation when installing in Program Files); the script does not declare a per-user install mode. The Linux AppImage runs as the invoking user. Neither package is signed in the first preview.

Bundled components and network

Section titled “Bundled components and network”

Runner archives include a relocatable CPython runtime and notices. The desktop app and runner contain no telemetry or phone-home client. Flowbook tasks can use the network. The Action’s downloads, cache, report/artifact uploads and summary publication communicate with GitHub as described above.

Out of scope

Section titled “Out of scope”

This model does not defend against malicious Flowbooks, compromised CI agents, operating systems or dependencies; stolen credentials; deliberate exfiltration by a task; or unsafe sharing of reports. The product provides no command sandbox.
