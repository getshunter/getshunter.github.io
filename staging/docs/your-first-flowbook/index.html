Section titled “Run it”

Validate before running:

--var overrides a Flowbook variable for that run. Repeat it for multiple variables. Commands run in the current environment and have the current user’s permissions, so review Flowbooks before running them.

Add build, test, and package steps

Section titled “Add build, test, and package steps”

The CMake starter sample is a small complete CMake/C++ project. Its Flow configures, builds, and runs CTest; the same pattern applies to your project:

working-directory is a run-command property. environment, output-variable, and stop-on-failure are task-level common properties. output-variable stores the task’s captured output in a Flowbook variable. stop-on-failure controls whether a failure stops the surrounding task sequence; it defaults to true.

Use another run-command for packaging, or use a core task such as Publish Artifact to stage selected files for CI collection. See the task reference and Flowbook format for other task types and common properties.

Script-based projects

Section titled “Script-based projects”

The Node starter sample uses npm install, npm test, and npm pack with no third-party dependencies. It demonstrates a script project without relying on a Shunter-specific package manager task. For Python, the same run-command task can invoke your project’s environment, for example python -m pytest.

The existing control-flow sample shows an if branch, task groups, Flow calls, and error handling. Use it when your build needs conditional steps. See Running in CI to run the same Flowbook in a provider job.
