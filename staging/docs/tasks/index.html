Task reference

Task types are declared by the generated Flowbook schema. This table lists each type available in the preview with its main task-specific properties. Most task types also accept applicable common properties such as enabled, stop-on-failure, environment, timeout-seconds, and retry settings. The schema is authoritative for valid fields and value types.

Type What it does Main properties
comment Adds a note without executing work. comment
run-command Runs a process and checks its exit code. command, working-directory, expected-exit-code, wait-for-completion
create-directory Creates a directory and its parents. directory, create-parent-directories
check-file-directory Checks whether a path exists and has the requested kind. path, kind, expectation
delete-directory Deletes a directory tree after safety checks. directory, delete-tree, repository deletion options
create-text-file Writes text to a file. file-path, file-contents, overwrite
run-python Runs a Python script or inline code. run-python-script, path-to-python-script, run-inline-python-script, inline-python-script
set-variable Assigns a literal, expanded text, an expression, file contents, or text extracted from a prior task’s logged output. For source: TaskOutput, an empty source-task selects the previous executed task in the same flow/call/iteration; otherwise it selects that task ID. The source is the task’s combined logged output (stdout and stderr when logging is enabled), not its output-variable. A non-empty regex selects the numbered regex-group (default 1); no match fails the task. Use output-variable plus extract-text when you need a task’s captured output independently of its logged presentation, or need extract-text’s UTF-8, match-index, multiline, or case-insensitive options. variable-name, variable-value, source, source-task, regex, regex-group
construct-path Joins path components using selected path rules. input-var, output-var, path normalization options
get-path-component Extracts a selected component from a path. input-var, output-var, component
if Runs child tasks when a Python expression is true. condition

Conditions and Flow variables

Section titled “Conditions and Flow variables”

if and else-if conditions are Python expressions. Shunter evaluates the expression and takes the branch when its result is truthy. Flow variables are strings in the variables mapping, so read one with variables.get("Name"); for example, variables.get("RunTests") == "true". The expression also has env (process environment mapping), task and workflow namespaces, the flow API object, and Python built-ins. Variable interpolation such as ${Name} is expanded before Python evaluation.
