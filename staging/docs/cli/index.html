shunt command-line reference

shunt runs a Flowbook without the desktop app. The Debug build used for this reference prints the full option list with shunt --help; check shunt --version when diagnosing a packaged runner.

Commands

Section titled “Commands”
Command Purpose
shunt run <flowbook> [options] Run a Flowbook. Passing the Flowbook path as the first argument is a shorthand for run.
shunt validate <flowbook> [--flow <id-or-name>] [--format human|json] Validate the document, or check the selected Flow and its reachable tasks. Human diagnostics are the default.
shunt schema Print the canonical Flowbook JSON Schema to standard output.
shunt ci-setup <provider> <flowbook> [options] Print a provider configuration, or write it to a new path with --output. Providers are github, gitlab, azure, jenkins, and bamboo.
shunt publish-summary <report.md> [--report-url <url>] [--ci <provider>] Publish an existing Markdown summary using the selected CI provider. shunt --publish-summary is an equivalent spelling.
shunt --help or shunt -h Print usage.
shunt --version Print the runner version.

The older run form shunt <flowbook> --ci-setup <provider> ... is also accepted. A subcommand word is treated as a command only when that path is not an existing file.

shunt ci-setup prints a minimal one-job starting point. Repositories with matrices, path filters, caches, or publish jobs should write their wrappers from the gallery examples, preserving the original action pins and provider-specific behavior.

shunt schema prints the same bytes as schemas/flowbook.schema.json. Installed runner packages include it at share/shunter/flowbook.schema.json; local build outputs place it beside shunt.

shunt validate --format json writes an array of issues to standard output and returns 1 if any issue is an error. Each object has stable severity, file, line, column, path, code, message, and hint keys. line and column are one-based when the YAML parser has a source mark and zero when only a JSON path is available. The human format remains the default and prints the same repair hints in readable form. Unknown keys may include a did you mean suggestion; task-level-only common fields and unexpanded run-flow Flowbook paths have dedicated diagnostics.

Run options

Section titled “Run options”
Option Meaning
--flow <id-or-name> or --workflow <id-or-name> Select a Flow; without it, run the first Flow in the file.
--task <task-path> Run one task.
--from <task-id-or-name-or-path> Run from a task through the end of the selected Flow.
--to <task-id-or-name-or-path> Run from the start of the selected Flow through a task.
--selection <id-or-name-or-path[, ...]> Run selected tasks.
--var <name=value> Override a Flowbook variable. Repeat for multiple values; text after the first = is preserved. For example, --var Configuration=Release.
--settings <file> Load machine settings for this run.
--html-log <path> Set the HTML report path. Its .json, .md, and .junit sidecars use the same stem. The path must not overwrite the Flowbook.
--no-html-log Disable the automatic report bundle and native CI publication.
--no-platform-info Omit the machine inventory from the HTML report.
--fail-on-ignored-failures Return a failed run if any task failure was allowed to continue with stop-on-failure: false.
--break <target> Add a breakpoint. Repeatable; targets can be task IDs, task paths, or flow-id:task-id-or-path.
--break-on-failure Pause after a stopping task failure.
--pause-timeout <minutes|Ns|Nm> Bound each debug pause from 1 second to 60 minutes. The default is 15 minutes.
--ci <auto|none|github|gitlab|azure|jenkins|bamboo> Select CI detection and reporting. auto detects the current provider; none disables CI integration.
--ci-defer-summary Delay summary publication for workflows that upload the report after the run.

--task, --from, --to, and --selection select partial execution scopes. Select tasks by ID, explicit task name, or numeric task path (such as 0/1). An unmatched or ambiguous selector fails and lists valid task IDs and names. Use one scope option at a time.

CI setup options

Section titled “CI setup options”

These options apply to ci-setup or the --ci-setup run form:

Option Meaning
--flow <id-or-name> Select the Flow the generated wrapper runs.
--output <new-file> Write the generated configuration to a path that does not already exist. Without it, print the configuration.
--runner-version <version> Set the exact four-part runner version in the generated setup.
--ci-os <linux|windows> Select a target OS when the provider template supports one.
--runner-repository <owner/repository> Set the GitHub repository used for runner release assets.
--ci-manual Generate a manually dispatched workflow; GitHub only.
--ci-archive-only Skip the Jenkins HTML Publisher setup and archive the report as a build artifact. Jenkins only.

Summary publication options

Section titled “Summary publication options”

publish-summary accepts --report-url <url> to add a report link and --ci <provider> to select the summary destination. It also reads SHUNTER_REPORT_URL, SHUNTER_ARTIFACTS_URL, and SHUNTER_TEST_RESULTS_URL when corresponding links are available.

Environment variables

Section titled “Environment variables”

These variables configure runner behavior. Other operating-system variables remain inherited by child commands and can be expanded in a Flowbook with $env{NAME}.

Variable Effect
SHUNTER_DEBUG_BREAK Comma-separated breakpoint targets for a run.
SHUNTER_DEBUG_BREAK_ON_FAILURE Enables pause-on-failure with 1, true, yes, or on; disables it with 0, false, no, or off.
SHUNTER_DEBUG_PAUSE_TIMEOUT Default debug pause timeout in minutes, or seconds/minutes with Ns or Nm suffix.
SHUNTER_REPORT_URL Default report link used by publish-summary.
SHUNTER_ARTIFACTS_URL Artifact link added to a published summary.
SHUNTER_TEST_RESULTS_URL Test-results link added to a published summary.
SHUNTER_PYTHON Optional path to the Python interpreter for Python tasks and conditions.
SHUNTER_PYTHON_WORKER Optional path to the Python worker script.
GITHUB_STEP_SUMMARY GitHub Actions Markdown summary destination.
GITHUB_OUTPUT GitHub Actions output file used by generated wrappers and the public Action.
USER, HOME, USERPROFILE Read for the current user and home-directory file-safety checks.
ComSpec On Windows, the command shell used by process tasks.

On Windows, run-command uses ComSpec (normally cmd.exe). Its built-ins such as del, copy, and rd take precedence over package executables with the same name, including tools in node_modules\.bin. An npm script written for Ubuntu CI can therefore behave differently on Windows. Run the Flow locally on the same OS family as CI when possible, such as Linux under WSL for an Ubuntu job. If your local OS differs, record that in the report instead of editing upstream scripts. Waited command tasks run with empty standard input, so interactive prompts fail fast. Migrated commands should pass non-interactive flags such as /q, -y, or --yes, or set CI=true.

Reports and logs

Section titled “Reports and logs”

By default, each completed run writes <flowbook-stem>-<final-run-id>.html, .json, .md, and .junit beside the root Flowbook. The run ID comes from CI when available, or from the Flowbook’s generated run ID. --html-log <path> changes the HTML bundle path and the sidecars use that stem. --no-html-log disables the automatic bundle and native CI publication. Task output is printed to the terminal; the HTML report contains the detailed run record. A desktop run keeps its report in execution history.

See Running in CI for report contents, provider behavior, and setup guidance.

Exit codes

Section titled “Exit codes”
Code Meaning
0 Command succeeded, validation passed, or the Flow completed successfully.
1 Flow failed, validation found an error, CI setup or summary publication failed, or report export failed.
2 Command-line usage or option error.
130 Interrupted with Ctrl+C / SIGINT.
143 Interrupted by SIGTERM on POSIX systems.
